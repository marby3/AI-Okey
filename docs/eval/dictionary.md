# スケルトン索引辞書の大きさと速さ（v0.3.0）

Mozc の dictionary_oss（コミット `0136c357`）から作った `aiokey.dic` の計測結果。
計測環境：MS-R1（aarch64、12 コア）の dev コンテナ（CPU 2、メモリ 1.5GB の上限つき）、release ビルド。

## 大きさ

暫定目標は 75MB 以下（全体 100MB 前後から逆算）。結果は **42.6MB**。

| 部分 | 大きさ | 中身 |
|---|---|---|
| trie | 7.2 MB | スケルトンのダブル配列（yada） |
| groups | 2.2 MB | スケルトンごとの語の範囲 |
| entries | 15.4 MB | 語の表（12 バイト × 約 128 万語） |
| readings | 5.5 MB | 読み（ひらがなを 1 文字 1 バイトで符号化） |
| strings | 9.2 MB | 表記（読みと同じか、読みのカタカナなら持たない） |
| pos_pairs | 0.0 MB | (lid, rid) の組 11,370 種 |
| conn_* | 3.1 MB | 連接コスト（行ごとの最頻値と、それ以外の値） |

詰める前（素直な形式）は 68.8MB だった。効いたのは次の 4 つ。

| 工夫 | 減った量 |
|---|---|
| 連接コストを、行ごとの最頻値と差分に分ける（最頻値でないセルは 12.4%） | 14.3 → 3.1 MB |
| 読みのひらがなを 1 バイトで持つ | 読み 12.7 → 5.5 MB |
| 表記が読みと同じ、または読みのカタカナなら持たない | 表記 約 11 → 9.2 MB |
| (lid, rid) を組の番号（u16）にし、読みの番号表をなくす | 語の表と番号表 21.0 → 15.4 MB |

### さらに詰めるなら

- trie と groups（9.4MB）：グループの開始位置を trie の値に直接入れれば、groups はほぼいらない。
- 語の表：コストを u8 に量子化すれば 1 語 11 バイトになる（変換の精度への影響を #7 で測ってから決める）。
- 全体 100MB の内訳（段2のモデル約 25MB、英単語辞書、実行ファイル約 8MB）を見て、#5 と #8 のあとで決める。

## 速さ

`cargo run --release -p aiokey-dictbuild --example open_bench -- target/aiokey.dic`

| 項目 | 結果 |
|---|---|
| 開く（mmap、CRC32 と構造の検証を含む） | 28〜58 ms（1 回目が遅い） |
| `lookup("htst")`（13 語） | 4〜13 µs |

開くのはサーバーの起動時に 1 回だけ。
