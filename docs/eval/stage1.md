# 段1（ラティスと N-best）の速さ（v0.4.0）

`cargo run --release -p aiokey-cli -- bench --iterations 50`

計測環境：MS-R1（aarch64）の dev コンテナ（CPU 2、メモリ 1.5GB の上限つき）、release ビルド、K = 32。
入力は、ふつうの文 8 つの読みをスケルトンにしたもの（平均 23.9 文字）。

| 項目 | 結果 |
|---|---|
| p50 | 3.5 ms |
| p95 | 4.9 ms |
| max | 7.5 ms |

暫定目標（20 文字程度で p95 20ms 以内）に対して、約 4 分の 1。

## 速さのために入れた工夫

- Viterbi では、位置ごとに「直前の語の rid ごとの最小コスト」と「次の語の lid ごとの結果」をまとめ、
  連接コストを引く回数を品詞の種類数の積に抑えた。
- 同じ区間・同じ読み方に置く辞書の語を、コストの低い順に 40 語までに絞る（`MAX_ENTRIES_PER_SPAN`）。
  文字列（読み・表記）は、残す語だけ取り出す。
- A* は、1 回に広げる前の語を 64 までにし、取り出す回数を 5 万回までにした。

## 追い込みの余地

p95 が目標の 4 分の 1 なので、精度の側に予算を回せる。#7 の評価（再現率@K）を見て、次を決める。

- `MAX_ENTRIES_PER_SPAN` を上げる（再現率が上がる代わりに遅くなる）。
- K を 32 より増やす（段2の採点時間とのかね合い）。
- 段1の時間は、段2（#8）と合わせた 50ms の予算の中で決める。

## 文の途中の `/`（#47、v1.0.1）

文の途中の `/` は、英語の指定とも「・」とも読む。「・」のコストは `MIDDLE_DOT_COST`（辞書にない語の半分、4500）。
`aiokey-cli convert`（K = 32、Mozc の辞書）での上位 5 件：

| 入力 | 1 位 | 「・」を含む最初の候補 |
|---|---|---|
| `zyq/F/knd` | 準Fknd | 5 位：準F・化など |
| `htst/hqt` | 果たしてhqt | 4 位：果たして・ヒント |
| `htst/keyboard` | 果たしてkeyboard | 5 位：果たして・keyboard |

「ジョン・F・ケネディ」の順位：

| 「・」のコスト | 順位 |
|---|---|
| 0 | 563 位（ただし `htst/hqt` の上位 3 件がすべて「・」の候補になり、英語の指定が 1 位から外れる） |
| 4500（採用） | `aiokey-cli convert -k 30000` でも出ない（テストは K = 3000 で順位を出す） |
| 7000 | —（「・」の候補が `zyq/F/knd` で 28 位まで下がる） |

段1は文全体で順位を付けるので、「ジョン」（`zyq` で 4 位）と「ケネディ」（`knd` で 11 位）の組み合わせは
順位が掛け算で下がる。名前のような複合語は、#34（文節ごとの変換）と #39（精度）で扱う。
