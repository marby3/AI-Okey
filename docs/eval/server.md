# 変換サーバーの負荷を抑える仕組みと既定値（v0.10.0）

`aiokey-server` は、段1（辞書と n-gram）を要求ごとにその場で計算し、段2（AI 採点器）は裏で次のときだけ動かす。
既定値はどれも暫定で、`config.toml`（`crates/aiokey-server/src/config.rs` に書式）で変えられる。

| 仕組み | 既定値 | 設定 |
|---|---|---|
| キー入力が止まったときと、変換キー（`Convert`）のときだけ段2を動かす | 30 ms | `stage2.debounce_ms` |
| 段1の 1 位と 2 位のコスト差がこれ以上なら段2を呼ばない | 3000 | `stage2.skip_cost_gap` |
| 段2のモデルを使わなければ解放し、次に要るときに読み込み直す | 600 秒 | `stage2.unload_after_secs` |
| 推論のスレッド数 | 2 | `stage2.threads` |
| プロセスの優先度（unix では nice 10） | BELOW_NORMAL | `priority` |
| 段2の 1 位と 2 位の確率の差がこれ未満なら「確信が低い」と知らせ、TSF はライブ変換を更新せずに候補ウィンドウを開く（v0.11.0） | 0.2 | `stage2.margin_threshold` |

段2の結果は、採点を始めたときと入力（revision）が同じときだけ使い、途中で入力が変わったら捨てる。
段2のモデルを設定しなければ（今の既定）、段2は使わない。学習済みのモデルを既定にするのは #13。
margin の閾値 0.2 は根拠のない暫定値で、#13 で学習済みのモデルの確信度を校正してから、dev セットで決め直す。

## コスト差の閾値（`skip_cost_gap`）

段1の 1 位と 2 位のコスト差ごとに、段1の 1 位が正解である割合を測った。
評価データは #7 と同じ test セット（jawiki-20261001 の 2000 記事）のうち正解が 10 文字以下の 3,708 例、K = 32、
段1単体の top-1 は 27.5%。

| 閾値 | 段2を飛ばす割合 | 飛ばした入力での段1の正解率 | 飛ばしたせいで取りこぼしうる割合 |
|---|---|---|---|
| 500 | 43.1% | 48.3% | 10.3% |
| 1000 | 21.1% | 72.6% | 3.1% |
| 1500 | 12.8% | 87.6% | 0.9% |
| 2000 | 8.9% | 92.7% | 0.4% |
| 2500 | 6.3% | 93.6% | 0.2% |
| **3000** | 4.9% | 95.6% | 0.1% |
| 4000 | 2.6% | 96.9% | 0.0% |
| 5000 | 1.2% | 97.7% | 0.0% |

「取りこぼしうる割合」は、段1の 1 位は誤りだが正解が K 件の候補の中にあった例の、全体に対する割合
（段2を飛ばさなければ当てられたかもしれない例）。

既定は安全側の 3000 にした。2000 にすると飛ばす割合がほぼ倍（8.9%）になり、失うのは 0.4%。
どこまで攻めるかは学習済みの段2の当たり方で決まるので、#13 で学習済みのモデルと合わせて測り直す。
