# 段1単体のベースライン（v0.7.0）

段2（AI 採点）を入れる前の、段1（辞書とラティスの N-best）だけの精度と速さ。#8 以降はこの数字と比べる。

## 条件

| 項目 | 値 |
|---|---|
| コーパス | Wikipedia 日本語版 jawiki-20261001 の先頭 2000 記事（`python -m aiokey.corpus --limit 2000`） |
| 評価データ | 記事単位で分けた test セットの 19,804 例（`python -m aiokey.datagen --splits test`） |
| 水増し | 既定値（母音を残す 20%、途中で切る 20%、文脈あり 50%） |
| 辞書 | `aiokey.dic`（Mozc dictionary_oss ＋ 同梱の英単語 262 語） |
| K | 32 |
| 計測 | `python -m aiokey eval --examples test.jsonl --dict build/aiokey.dic -k 32` |

## 精度

| 指標 | 結果 |
|---|---|
| 再現率@32（正解が上位 32 件に入る） | 20.0% |
| top-1 | 7.7% |
| top-5 | 13.8% |
| 打鍵削減率（通常のローマ字入力との比較） | 35.0% |
| 英単語を含む文（3,035 例）の top-1 | 0.1% |

打鍵削減率は、1 −（AI-O Key の入力の打鍵数 ÷ 通常のローマ字入力の打鍵数）。通常のローマ字入力は、
あ行 1・ほかのかな 2・ゃゅょ +1・っ 1・ー 1 で数える。ん は、子音（な行・や行を除く）の前なら n の 1、
母音・な行・や行の前と語末では nn の 2 とする（ふつうの IME の打ち方）。

## 速さ

| 項目 | 結果 |
|---|---|
| p50 | 3.7 ms |
| p95 | 5.1 ms |

## わかったこと

1. **長い文ほど当たらない。** 21 文字以上では再現率が 4.3% しかない。Wikipedia の文は中央値 22 文字と長く、
   全文を 1 回で当てる評価は、実際の使い方より厳しい。仕様では、長い入力は文節で区切り、確定した部分を
   文脈に回す（段1の 4）。この区切りは、変換サーバー（#10）で入れる。それまでは、短い入力（10 文字以下）の
   数字（再現率 54〜68%）が実用に近い。
2. **数字のあとの助数詞が当たらない。** `2000nq5gt` が「2000人5ごと」になり、「2000年5月」にならない。
   未知の数字を一般名詞として扱っているので、年・月・日などの助数詞とつながりにくい。→ #22
3. **辞書にない英字が崩れる。** `cd` を子音として読もうとし（c は子音ではない）、「cで」のようになる。
   大文字の略語（CD、JA）は、小文字で打つと表記を戻せない。英単語の辞書が同梱の 262 語しかないことも効いている。→ #23
4. **段2の上限は再現率@32 で決まる。** 段2は段1の候補から選ぶだけなので、全体では 20.0% を超えられない。
   段2（#8、#13）を入れる前に、2 と 3 で再現率を上げる余地がある。

## 速さの余地

p95 は 5.1ms で、暫定目標（20ms）の 4 分の 1。区間あたりの語数（`MAX_ENTRIES_PER_SPAN`）や K を増やして
再現率を上げる余地がある。段2の採点時間（#8）と合わせた 50ms の予算の中で決める。
