# 段2の学習データ（#41、v1.0.5）

段2（候補を並べ替えるモデル）を学習し直すためのデータ。今までは Wikipedia の 300 記事だけだった。記事を大きく増やし、
実際に打つ文に近い文章（会話文、話し言葉の読み上げ文、Web の文章）を加えた。GPU での学習と比較は #55 で行う
（手順は `docs/training-gpu.md`）。

**取得したデータも、データから作った学習の例も、リポジトリと配布物には入れない。** 置き場所の `data/` と `target/` は
`.gitignore` で除き、Release の配布物（`.github/workflows/release.yml`、`installer/`）にも入らないことを、テスト
（`python/tests/test_corpora.py`）で確かめている。リポジトリに置くのは、取得スクリプト（`scripts/fetch-corpora.sh`、
版と SHA-256 を `scripts/corpora.sha256` に固定）と、記事の形に直すコード（`python -m aiokey.sources`）だけ。

## コーパスの一覧と判断

どれも、段2の学習（候補の並べ替えのための情報解析）に使う。ライセンスで利用を許されたものでも、学習に使う根拠は
著作権法 第三十条の四と同じ考え方になる（下の節）。ライセンスは帰属表示（`NOTICE`）と、データそのものを再配布しない
方針の確認に使った。取得日は 2026-11-03。

| コーパス | 判断 | ライセンス | 中身と理由 |
|---|---|---|---|
| 日本語版 Wikipedia | 使う | CC BY-SA 4.0 | 今までの学習データ。ダンプ（jawiki-20261001）の先頭から 2 万記事に増やした。書き言葉で、固有名詞が多い |
| Tatoeba | 使う | CC BY 2.0 FR（一部 CC0。日本語の多くは田中コーパス由来でパブリックドメイン） | 日常の会話の短い文。実際に打つ文に近い。毎週の書き出し（2026-10-31 版）を使う。古い版は残らないので、取得スクリプトはハッシュが変わったら止まる |
| Common Voice | 使う | CC0 1.0 | 読み上げ用に集めた文（`server/data/ja` の 2 ファイル、コミット `1e772a6`）。話し言葉に近く、量は少ない |
| 青空文庫 | 使う | CC BY 4.0（globis-university/aozorabunko-clean の整えたデータ。元の作品は著作権の切れたもの） | 小説・随筆の会話文。今の表記に近い「新字新仮名」で、著作権の切れた作品だけを使う。量が多く（約 1 万作品・450 万文）文学に偏るので、2,500 作品に絞った |

| Livedoor ニュースコーパス | 使わない | CC BY-ND 2.1 | 改変禁止の条件があり、ニュースの文は Wikinews で足りる |
| 現代日本語書き言葉均衡コーパス（BCCWJ） | 使わない | 有償の利用契約（研究用） | 配布するモデルの学習には使えない条件 |

| 京都大学のコーパス（KWDLC など） | 使わない | 研究目的に限った利用 | 同上 |

## データの量

記事の形にしたあとの量と、そこから作った学習の例（`target/examples-v2`、2026-11-04）。例は train と dev の合計で、test の
記事（記事 ID のハッシュで 5%）は作っていない。段1の候補（K = 32）に正解がある例だけが学習に使える。

| コーパス | 記事（文書・作品） | 文 | 評価の文と同じで除いた文 | 例（train と dev） | 段1の候補に正解がある例 |
|---|---|---|---|---|---|
| Wikipedia | 20,000 | 2,758,891 | 12,433 | 2,604,981 | 529,654（20.3%） |
| Wikinews | 4,076 | 33,733 | 18 | 32,203 | 5,683（17.6%） |
| Tatoeba | 248,668 | 256,184 | 6 | 243,445 | 103,503（42.5%） |
| Common Voice | 11,048 | 12,144 | 4 | 11,517 | 4,486（39.0%） |
| 青空文庫 | 2,500 | 978,100 | 93 | 936,639 | 138,903（14.8%） |
| Web（FineWeb-2） | 100,000 | 2,638,771 | 295 | 2,507,593 | 779,282（31.1%） |
| 合計 | 386,292 | 6,677,823 | 12,849 | 6,336,378 | 1,561,511（24.6%） |

- 今まで（Wikipedia 300 記事）の学習に使えた例は 19,216 だったので、**約 81 倍**になった。
- `train.jsonl` には段1の候補に正解がある例だけを書いた（1,479,128 例、2.6 GB、gzip で 413 MB）。`dev.jsonl` は全部の例
  （326,635 例、1.0 GB、gzip で 114 MB）。GPU での学習は、ここから段階的に無作為に選んで使う（`docs/training-gpu.md`）。
- 生成は dev コンテナの 10 並列で約 8 時間かかった（1 秒あたり約 220 例。Wikipedia の長い文が遅い）。
- 文の長さは今までと同じく 4〜80 文字。会話文を 1 文のまま残すよう、句点の直後が閉じかっこなら切らないようにした
  （「はい、出来ます。」と答えた。が 2 つに切れていた）。
- 評価の文と同じで除いた文は、Wikipedia の見出しや一覧の項目（「サッカー」「姉妹都市」など、多くの記事に出る短い行）が
  ほとんどだった。

## 評価に使う文を除く

評価に使う文と同じ文は、学習の例にも、次の文の文脈にも使わない（`aiokey.datagen --exclude`）。比べるときは、全角・半角の
違いと前後の空白を無視する（Unicode の NFKC で正規化）。除く対象は次の評価の例の正解：

- test セット（`target/examples2000/test.jsonl`、`target/examples/test.jsonl`、`target/eval/test.jsonl`）
- ATC 2026（`target/eval/atc.jsonl`。文と句の両方）
- 固有名詞の 40 文（`target/eval/proper.jsonl`）

Wikipedia の test の記事は、今までと同じく記事 ID のハッシュで分けているので、学習（train / dev）には入らない。Web の
コーパスに Wikipedia の文の写しがあっても、同じ文なら除かれる（言い回しが少しでも違う文は除けない）。

## Web のコーパスを使う法的な根拠

Web から集めたコーパス（FineWeb-2 の日本語）は、文章の著作権を書いた人が持っている。ライセンスで利用を許されたものでは
ないので、**著作権法 第三十条の四**（著作物に表現された思想又は感情の享受を目的としない利用）を根拠に使う。
ここに書くのは、このプロジェクトとしての判断の記録で、法律の専門家による助言ではない。

### 条文

e-Gov 法令検索（著作権法、昭和四十五年法律第四十八号）の第三十条の四から、柱書き・ただし書きと、関係する第二号を引く：

> 著作物は、次に掲げる場合その他の当該著作物に表現された思想又は感情を自ら享受し又は他人に享受させることを目的としない
> 場合には、その必要と認められる限度において、いずれの方法によるかを問わず、利用することができる。ただし、当該著作物の
> 種類及び用途並びに当該利用の態様に照らし著作権者の利益を不当に害することとなる場合は、この限りでない。
>
> 二 情報解析（多数の著作物その他の大量の情報から、当該情報を構成する言語、音、影像その他の要素に係る情報を抽出し、
> 比較、分類その他の解析を行うことをいう。第四十七条の五第一項第二号において同じ。）の用に供する場合

解釈は、文化審議会著作権分科会法制度小委員会「AI と著作権に関する考え方について」（令和 6 年 3 月 15 日、
<https://www.bunka.go.jp/seisaku/bunkashingikai/chosakuken/pdf/94037901_01.pdf>。以下「考え方」）に沿って判断した。
「考え方」自体に法的な拘束力はない。

### この使い方が第三十条の四に当たる理由

- **目的は情報解析（第二号）。** 文章を人が読んで楽しむ（享受する）ためではなく、大量の文から「打った子音・母音の並びと、
  文脈の中で選ばれる表記」の対応という統計的な情報を取り出して、変換候補の並べ替えに使う。
- **出力は学習した文章を再現するものではない。** 段2の出力は、利用者が打った入力に対する変換候補の確率で、学習データの
  文章を出すためのものではない。「考え方」が享受目的の併存する例に挙げる、学習データの創作的表現を意図的に出力させる
  ための追加学習（意図的な過学習）は行わない。学習は dev の損失が良くならなくなったら止め、いちばんよかった時点を使う
  （`python -m aiokey train --eval-every --patience`、#41 の基準 5）。
- **必要と認められる限度。** 使うのは公開のデータセットの 1 ファイル（日本語の train の `000_00000.parquet`）のうち、
  決めた数の文書だけ（下の「データの量」）。文に分け、4〜80 文字の日本語の文だけを残し、例を作ったあとの段階で使う。

### ただし書き（著作権者の利益を不当に害する場合）に当たらないと判断した理由

- **情報解析用の有償のデータを避けて集めるものではない。** 「考え方」は、ただし書きに当たり得る例として、情報解析に使える
  形に整理したデータを有償の API で提供しているのに、それを使わずにウェブサイトから集める場合を挙げている。使うのは、
  Common Crawl（公開のクロール）から作られ、誰でも取得できる公開のデータセットで、個別のサイトから集めたものではない。
- **AI 学習を拒む技術的な措置を回避していない。** 「考え方」は、robots.txt などでクローラを拒む措置が、ただし書きを判断する
  事情になり得るとしている。Common Crawl は収集のときに robots.txt を守っており、FineWeb-2 にはサイトの管理者や本人が
  削除を申し出る窓口がある。このプロジェクトは自分でクロールしない。
- **作品の市場と競合しない。** 学習したモデルは変換候補の並べ替えに使うだけで、元の文章を読む代わりにはならない。データ
  そのものも配布しない（下の「データの扱い」）。
- **海賊版について。** FineWeb-2 は元の FineWeb の URL のフィルター（有害なサイト・成人向けのサイトを除く）を通して
  いるが、違法にアップロードされた文章を除くフィルターではなく、混じっている可能性はゼロではない。「考え方」は、海賊版と知りながら集めることや、海賊版サイトの運営を助けることに注意を促している。
  このプロジェクトは海賊版サイトから集めておらず、そのようなサイトへのアクセスも生じない。権利者から申し出があれば、
  その文書を除いて学習し直す。

### コーパスのライセンス・利用規約

- **FineWeb-2**（<https://huggingface.co/datasets/HuggingFaceFW/fineweb-2>、版 `af9c13333eb981300149d5ca60a8e9d659b276b9`）：
  データセットは **ODC-By 1.0**（Open Data Commons Attribution License）。帰属を表示する（`NOTICE`）。メールアドレスと
  公開の IP アドレスは置き換え済みだが、ほかの個人情報が残る可能性はデータセットの説明にも書かれている。
- **Common Crawl の利用規約**（<https://commoncrawl.org/terms-of-use>）：FineWeb-2 の利用はこの規約にも従う。違法な目的に
  使わないこと、第三者の著作権などを尊重すること、収集した内容とは別に個人情報を集めないことを求めている。学習には
  文の並びだけを使い、個人情報を取り出して集めることはしない。

### データの扱い

- **リポジトリに入れない。** 取得したファイルは `data/corpora/`、記事と学習の例は `data/corpora/articles/` と `target/` の
  下に置く。どちらも `.gitignore` で除いている。
- **配布物に入れない。** Release の配布物はインストーラー、変換エンジン、辞書（`aiokey.dic`）、段2のモデル
  （`aiokey-stage2-q8_0.gguf`）、設定、`LICENSE`・`NOTICE` だけで、コーパスも学習の例も含まない。
- **学習のサーバーには学習の例だけを送る。** GPU サーバーに送るのは、文から作った学習の例（`train.jsonl`・`dev.jsonl`）
  だけで、学習が終わったら消す（`docs/training-gpu.md`）。
- **国外での扱い。** 第三十条の四は日本の法律。配布するモデルを国外で使うときの扱いは、その国の法律による。

## CPU で流した確認

新しいデータ（`target/examples-v2` の先頭 400 例を gzip にしたもの）で、学習が最後まで流れることを手元の CPU で確かめた
（dev コンテナ、2 スレッド、2026-11-03）：

```bash
python -m aiokey train --train train.jsonl.gz --dev dev.jsonl.gz --train-sample 120 --dev-sample 60 \
  --device cpu --epochs 3 --max-batch-tokens 4096 --lr 2e-4 --eval-every 5 --patience 2
```

- 無作為に選んだ 120 例で学習し、5 ステップごとに dev（60 例）を測った。dev の decision loss は 20.91（学習前）から
  60 ステップ目の 4.84 まで下がり、65・70 ステップ目に 2 回続けて上がった（5.01、5.36）ので、210 ステップ中の
  **70 ステップで止まった**。
- いちばんよかった 60 ステップ目に戻してから、温度を校正し（4.24）、GGUF（Q8_0、25.6 MB）に書き出した。書き出した
  GGUF は採点器（`aiokey.Scorer`）で読める。
- かかった時間は 49 分（dev を 15 回測った時間を含む。GPU での見積もりは `docs/training-gpu.md`）。
- CPU での学習は 1 ステップの中間の値が大きく、`--max-batch-tokens 8192` では 4 GB に収まらなかった。GPU（16 GB）は
  #13 と同じ `--max-batch-tokens 32768` でよい。
